# OpenCode Session Recovery Analysis

## What Happened

When OpenCode updated from **v1.18.14** → **v1.18.25**, the database at `~/.local/share/opencode/opencode.db` was **completely reset**. The new version created a fresh empty database with a new schema (event-sourced architecture with tables: `permission`, `event`, `event_sequence`, `credential`, `control_account`, `account`, `account_state`, `data_migration`, `workspace`, `session_context_epoch`).

The old database that held all your session data was overwritten. The current DB is only **4KB** (empty), and the WAL file (1.8MB) only contains data for a single new session created after the update.

## What Can Be Recovered

### ✅ Recoverable
- **Session metadata**: Session IDs, creation timestamps, workspace/project directories, slugs, parent session relationships
- **Activity timeline**: Which models were used, when sessions were active, agent types (build/plan/explore)
- **Your prompt inputs**: 50 most recent prompts from the CLI history
- **Session titles**: Including auto-generated titles like "Explore llamux codebase", "Find archived sessions location", etc.

### ❌ NOT Recoverable
- **Full chat message content** (AI responses, tool outputs, code suggestions) — this was stored exclusively in the SQLite database which was reset
- **File diffs and code changes** generated by OpenCode — only logged as metadata (tool calls), not full content

> [!CAUTION]
> The actual conversation history (the messages you exchanged with the AI) was stored in the SQLite database. Since that database was reset during the update and no backup exists, **the full chat history cannot be recovered**. The server log captures *that* conversations happened and *which models were used*, but not *what was said*.

## Recommended Next Steps

1. **File a bug report** with OpenCode — the update should not silently destroy user data. They may have a migration path or a way to recover from the old DB format.
2. **Downgrade to v1.18.14** temporarily to check if the old binary can read any remaining data (unlikely since the DB file was overwritten, but worth trying).
3. **Close stale tabs** in the desktop app to stop the "session not available" errors.
4. **Enable automatic backups** going forward for `~/.local/share/opencode/opencode.db`.
