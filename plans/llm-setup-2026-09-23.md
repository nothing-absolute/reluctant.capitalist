# LLM Setup — Findings & Cloud Hosting Plan (2026-09-23)

Context: the "AI polish pass" in this repo runs structured JSON extraction + markdown
rewriting over note candidates (135 candidates, ~732KB total input) through a local
LLM via `scripts/polish.mjs` (OpenAI-compatible HTTP client).

## Why the phone-side plan was paused

A Unihertz Tank 3 Pro (Dimensity 8200, 16GB, Termux llama.cpp CPU-only) ran Qwen3-4B
~5.3 tok/s sustained. The full batch was estimated at **~13 hours** on the phone
(~244k output tokens across 135 candidates). Too slow → pivot to cloud GPU.

## Findings worth reusing with any LLM

### Qwen3 "thinking" quirk (root cause found)
- The bartowski `Qwen_Qwen3-4B-GGUF` Q4_K_M ships with thinking **enabled** via its `chat_template`.
- `chat_template_kwargs: { thinking: false }` is **ignored**.
- `chat_template_kwargs: { enable_thinking: false }` **works** — verified 0.7s direct reply,
  no `reasoning_content`, finish `stop`. It's a **per-request kwarg** (no server restart).
- `scripts/polish.mjs` now sends this kwarg in its `chat()` body.

### Model URLs (verified)
- `https://huggingface.co/bartowski/Qwen_Qwen3-4B-GGUF/resolve/main/Qwen_Qwen3-4B-Q4_K_M.gguf` (2,497,280,960 B)
- 1.7B fallback: `Qwen_Qwen3-1.7B-Q4_K_M.gguf` (1,282,439,584 B)
- bartowski repo has no "no-thinking" GGUF variant; thinking is template-controlled (the kwarg handles it).

### Measured phone throughput (Tank 3 Pro, CPU only)
- Fresh: ~5.5 tok/s (50 tokens / 8.95s).
- Sustained with thinking ON: ~2.9 tok/s (600 tokens / 204.8s).
- With `enable_thinking:false` (clean test): 141 tokens / 29.9s ≈ **5.26 tok/s** (prompt 10.64 tok/s).
- Device thermally throttles as it warms (5.5 → ~3 tok/s).

### Termux setup approach (historical record)
- `scripts/termux-setup.sh`: Cloudflare mirror, clang deps, OpenMP off, llama-server
  `-c 16384 -t 6 --alias qwen3-4b`, served on the phone's LAN HTTP endpoint.
- Phone `http://10.84.161.108:8080`, laptop `http://10.84.161.15:8765/` (temp static server for scripts).

### polish.mjs integration contract
- Reads only `choice?.message?.content`; `stripThinking()` strips inline `thinking...\nresponse\n` only.
- `temperature:0.3`, `max_tokens` capped 4096, `TIMEOUT` 900s, `MAX_INPUT_CHARS` 20000.
- CLI: `--approved`, `--diff`, `--apply`, `--force`, file specs `<section>/<file>`.
- Dry-run writes `.polished.md` + `polish/diffs/` + `polish/POLISH.md`; `--apply` mutates source.
- Verified end-to-end against the phone server: `npm run polish -- 20260923-20260923-182419 garden/writing-style`.

## Cloud GPU cost breakdown (Sept 2026, verify at click time)

For this workload: ~183K input / ~200K output tokens per full 135-candidate batch, JSON
output, sporadic (daily → weekly re-polish). No minimums, pay-as-you-go everywhere.

### Tier 1 — Managed serverless APIs (easiest, no GPU to babysit)
Per-token billing; the OpenAI-compatible client in polish.mjs works with only `POLISH_API`/`POLISH_MODEL` set
(plus an `Authorization: Bearer` header — one small code change needed).

| Provider / model | $ per full batch (≈0.18M in / 0.2M out) |
|---|---|
| Together — Qwen3.5-9B ($0.17/$0.25 per 1M) | **~$0.08** |
| Fireworks — gpt-oss-20b ($0.05/$0.20 per 1M) | **~$0.05** |
| Baseten / Modal / Replicate (hosted open model) | ~$0.10–1.00 |

### Tier 2 — Your own GPU, serverless (RunPod — easy + reliable, per-second, scale-to-zero)
Self-host llama.cpp/Qwen GGUF on your pick of GPU.

| GPU class | Rate (/sec) | Full batch (~0.5–1h) |
|---|---|---|
| A4000 16GB | $0.0002 Flex / $0.00012 Active | **~$0.60–1.00** |
| A5000/24GB class · L4 · 3090 class | $0.00026–0.00034 | **~$0.70–1.20** |
| A6000 48GB | $0.00048 Flex / $0.00029 Active | **~$1.00–1.20** |

### Tier 3 — Cheapest $/hr (Vast.ai marketplace)
One-off batch runs, best when interruptible is OK. Download model, run batch, tear down.

| GPU | $/hr | Full batch (~1–2h incl. setup) |
|---|---|---|
| RTX 4090 24GB spot | **~$0.32–0.37** | **~$0.30–0.75** |

### Recommended path
1. **Today / one-off:** RunPod Serverless A4000 or L4 (=**~$1**) OR a hosted token API
   (Together/Fireworks, **~$0.05–0.08**) — both zero-ops, no monthly cost.
2. **If this becomes a recurring daily/weekly job:** cheaper with RunPod "Active" workers
   (40% discount) or Vast.ai spot; expect **~$0.05–$2/batch** depending on provider.
3. **Model quality upgrade:** go from Qwen3-4B up to Qwen3-14B or Qwen3-30B-A3B MoE (fits 24GB)
   for materially better structured-JSON adherence; still minutes not hours on any 24GB+ GPU.
