2026-08-27: Odysseus Development Updates

08:55 - Imported all opencode sessions into Odysseus

Ran an idempotent importer (/tmp/opencode/import_opencode_to_odysseus.py) reading opencode.db read-only -> odysseus app.db via its own ORM (oc- prefixed ids, owner dickman, readable model labels, epoch-ms -> naive UTC timestamps). Result: 283 sessions / 7815 messages in the db, FTS-indexed via DB triggers. Startup then hung for minutes because the _migrate_chat_messages_fts backfill uses a correlated NOT EXISTS against FTS5 -> O(n²) rescan once transcripts grew to thousands of rows. Fixed in core/database.py by backfilling missing FTS rows with a Python-side set (set-based, idempotent); boot dropped from minutes to ~10s. Server now running from the original source path on :7000 with all built-in MCP servers connected (Memory/Email/Browser/Image gen/RAG). Tool-only assistant turns imported as a [tools: ...] line so no turns are lost. Takeaway: FTS5 backfills at boot should never use correlated subqueries against the FTS table.

Configured the cookbook (in both the source repo [local path redacted] and the deployed copy on the 500GB drive) so local HF model downloads land in data/local instead of ~/.cache/huggingface/hub. Two layers: (1) state - data/cookbook_state.json. Local server now has modelDirs incl. the target and downloadDir=[local path redacted] (models land under data/local/hub/models--org--name/ via HF_HOME/HF_HUB_CACHE, resumable blobs per issue #2722); (2) backend - new MODEL_DOWNLOAD_DIR constant in src/constants.py (default <DATA_DIR>/local, override ODYSSEUS_MODEL_DOWNLOAD_DIR) applied in routes/cookbook_routes.py model_download when local_dir is absent for non-ollama/local downloads. Remote hosts keep their own HF cache. Requires app restart; systemd odysseus-ui.service is currently a placeholder that exits 217.

20:10 - Wired OmniRoute (LLM router) into Odysseus as a first-class provider

In [local path redacted], integrated the self-hosted OmniRoute gateway (http://localhost:20128, key OMNIROUTE_API_KEY) in code (not just config): (1) src/constants.py - OMNIROUTE_BASE_URL (default http://localhost:20128) + OMNIROUTE_API_KEY; (2) src/llm_core.py _detect_provider - added omniroute check BEFORE the localhost-ollama check (bare localhost URLs fall to native ollama /api/chat, so OmniRoute on localhost was being misdetected as ollama → /chat instead of /v1/chat/completions); (3) src/model_discovery.py - surfaced a dedicated omniroute provider in get_providers() that live-fetches /v1/models (found 1002 model aliases) and added its host/port to the scan; (4) src/endpoint_resolver.py build_chat_url - /v1/chat/completions for provider=omniroute (normalizes a base already ending in /v1); (5) app.py _ensure_omniroute_endpoint() - idempotent startup seed that upserts a ModelEndpoint (base http://localhost:20128, key, supports_tools=True), never clobbers an admin key, and only adopts OmniRoute as default if no usable endpoint exists. Verified live: auto/best-coding + auto/best-reasoning return 200 (auth accepted, routed). Some aliases 401/410/418 are OmniRoute dashboard upstream config (deprecated/anti-abuse), not wiring. Semantic gotcha: build_chat_url only inserts /v1 for api.openai.com today - OmniRoute (pathless localhost) needed an explicit branch.

22:20 - Free/open-source video gen LLMs to add into Odysseus

Odysseus already has a video.generate capability slot + FAMILY_VIDEO/CAP_VIDEO_GENERATION wired in src/model_capabilities.py, plus an image_gen_server.py MCP pattern, but no video-gen tool yet. Candidates (2026): Wan2.2 (Alibaba, Apache 2.0, T2V+I2V, runs on ~14GB consumer VRAM) - strongest open option; HunyuanVideo 1.5 (Tencent, 3B, custom license excludes EU/UK/SK); LTX-2 (Lightricks, T2V with synced audio, 4K/50fps, free <$10M revenue); CogVideoX (Zhipu, MIT repo, varies by checkpoint); Mochi 1 (Genmo, Apache 2.0); Kandinsky 5.0 (MIT); Stable Video Diffusion (baseline, common Diffusers tooling). All are downloadable weighting (not "LLMs" in the text sense) - integrate by adding a video_gen MCP server mirroring image_gen_server.py, or via the local Ollama/OmniRoute endpoint pattern. Note: Wan2.2 = best quality+license; LTX-2 = only one with native audio. Check exact checkpoint license before commercial use.
