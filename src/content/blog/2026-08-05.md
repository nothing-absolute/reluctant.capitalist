07:30 - XFCE window-monitor restore daemon (fixed & working)
Built `~/.local/bin/xfce-monitor-restore.py` — background daemon that keeps each window on its monitor after display layout changes (xfwm4 dumps windows to the extended display otherwise). Autostart added: `~/.config/autostart/xfce-monitor-restore.desktop`. Key X11 discoveries:
- **xfwm4 4.20.0 ignores `_NET_MOVERESIZE_WINDOW`** client messages (even the canonical wmctrl form). The reliable primitive is a **real `XConfigureWindow` on the client window** with `CWX|CWY` — xfwm4 places the frame exactly at the requested root-absolute coords (verified empirically; it honors ConfigureRequest via `handleConfigureRequest` → `clientMoveResizeWindow`).
- **python-xlib's `translate_coords` returns NEGATED coordinates** (bug). Use ctypes `XTranslateCoordinates` for correct absolute positions (matches xwininfo).
- Move = unmaximize (via `_NET_WM_STATE`) → configure → re-maximize; works.
- **Suspected root cause of the original jumping windows: HDMI-1 (plasma TV) position drifts every ~10s** (observed +321 → +334 → +298 over minutes), shifting windows along with it. Layout is being re-configured periodically — worth investigating what's doing it.

23:30 - PowerEdge R630 GPU Upgrade Reality Check
R630 is a 1U server: 3x PCIe 3.0 slots (2x low-profile half-length + 1x full-height half-length), max 1100W PSUs, but NO GPU power cables (no 6/8-pin PEG). Dell officially supports max ONE 75W single-wide GPU (e.g., Tesla T4/P4, A2, L4).
- Realistic drop-in: 1-2x Tesla T4 (16GB, 70W, slot-powered, low-profile) = 16-32GB VRAM total, 8GB/s each via PCIe 3.0 x16.
- Cards above 75W (P40/P100/3090) require power modding (external PSU or wiring into redundant PSU) and won't fit 1U height/length cleanly.
- Best LLM choice for slot power: 2x T4 (or A2), run vLLM/llama.cpp with GPU+CPU offload, 128GB RAM becomes huge KV-cache.
