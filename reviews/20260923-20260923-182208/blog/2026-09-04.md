**09:00 - Android Termux llama.cpp Setup**
Researched running llama.cpp on Android via Termux for local LLM hosting. Key points: install from F-Droid, build with cmake, use Q4_K_M GGUF models. Best lightweight models: Qwen3-0.6B, LFM-2.5-1.2B (10-18 tok/s on 4-6GB RAM). GPU acceleration possible via OpenCL on Qualcomm Adreno. Server mode exposes OpenAI-compatible API at localhost:8080.

**Script → Podcast Audio via Pocket-TTS (voice cloning)**
Spec: send a formatted script, get one finished audio file with humanized multi-speaker TTS, no further input. Selected Pocket-TTS via sherpa-onnx — offline zero-shot voice cloning on phone CPU (Dimensity 8200). One short reference WAV clones a voice; keep separate refs per speaker (your voice = host, others = guests). `sherpa-onnx-offline-tts` CLI: text → WAV, loop per line with per-speaker ref, concatenate into single file. Model: sherpa-onnx-pocket-tts-int8-2026-01-26.tar.bz2 (int8, on-device). Rethink: Pocket-TTS has only ONE fixed reference at a time per run; multi-speaker = re-invoke CLI per line with a different --reference-audio, then stitch. Qwen2.5-7B-Instruct-Q4_K_M.gguf (4.68GB, bartowski) = next local LLM on phone behind llama-proxy (baseURL http://127.0.0.1:11400/v1).

**FINAL TTS DECISION: Supertonic 3 (not Kokoro, no voice cloning)**
User chose Supertonic-3 via sherpa-onnx. Multi-speaker: 10 speakers `--sid 0-9`, one model, 31 langs, 44.1kHz, RTF ~0.097 CPU (fast than real-time). Pipeline: script → parse `SPEAKER: text` → per line `sherpa-onnx-offline-tts --supertonic-* model files --sid N --lang en --output-filename line_N.wav "text"` → concatenate WAVs → single output. Model: sherpa-onnx-supertonic-3-tts-int8-2026-05-11. Difference vs Kokoro = humanization/fidelity: Supertonic 44.1kHz flow-matching genuinely-human broadcast voice; Kokoro 24kHz, lighter (~155MB vs ~380MB) but less human. No voice cloning needed (fixed 10 distinct voices). Qwen2.5-7B confirmed LIVE through llama-proxy at 127.0.0.1:11400 → phone 10.240.190.108:8080.
