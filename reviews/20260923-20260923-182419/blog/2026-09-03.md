**Goal:** use an Ollama LLM to (1) review/rectify tags on all 89 existing notes to best fit content, and (2) power automatic tagging of all future notes (both via Opencode captures and Obsidian/Templater).

**Findings:**
- This laptop is **CPU-only** (Intel HD 5500, no CUDA; `size_vram: 0`), an **i7-5600U 4-thread**, **15GB RAM**.
- At time of testing RAM was ~exhausted (13Gi used / ~218Mi free) and load avg >5 → heavy swapping.
- Installed models: `qwen2.5:7b`, `qwen2.5-coder:7b`, `qwen2.5-coder:3b-instruct`, `phi3:mini`.
- Measured latency: **qwen2.5:7b exceeded 180s** for one note (never finished); **phi3:mini took 89s** for one note and produced messy multi-word tags (ignored `/` join).
- Conclusion: **7b is unusable here** (minutes/note); even 3b/phi3 ≈ 90s/note. A small general model (~1-1.5b, e.g. `llama3.2:1b` or `qwen2.5:1.5b`) should run in seconds/note and make both the 89-note review and future auto-tagging usable.

**Decision point (next session):** after restarting to free RAM, re-check `free -h` (and that Ollama is up via `curl localhost:11434/api/tags`), then choose the tagging model — prefer pulling a ~1-1.5b general model for speed; fall back to 7b only if RAM/load allows.

**Already built (resume point):**
- `/tmp/opencode/tag_notes.py` — multi-mode tool: `review` (re-tag all non-template notes), `tag <path>` (single new note, hot), `vocab` (prints seed tag vocabulary). Uses Ollama `format:json`. `TAG_MODEL`/`TAG_HOT_MODEL`/`TAG_DRY` env vars. Has `--dry-run`.
- Design: tags are a **virtual cross-folder index** — the prompt tells the LLM it MAY invent NEW tags (topics/projects/concepts) beyond the seed vocabulary, so an old note can be pulled into a folder/tag created later. Keep existing `type/*`, `project/*`, `topic/*`, `source/opencode` structure.
